# M1 可靠任务 walking skeleton 验证交接

验证日期：2026-08-25（Asia/Shanghai）

分支：`codex/m1-reliable-run-skeleton`

## 已验证范围

- `POST /api/v1/runs` 使用 `Idempotency-Key` 原子创建 run 与首个 outbox event；相同请求重放返回同一 run，不同请求冲突返回稳定错误。
- `GET /api/v1/runs/{id}`、`POST /api/v1/runs/{id}/cancel`、`GET /timeline` 与 `GET /events` 通过真实 FastAPI 路径验证。
- `audit_runs`、`run_steps`、`outbox_events` 从空 Control PostgreSQL 经 Alembic 升级创建。
- Transactional outbox 由 Celery Beat 周期调度；worker 将 no-op run 沿 12 个持久化状态版本从 `QUEUED` 推进到 `COMPLETED`。
- 状态机拒绝非法转换；run 更新使用 optimistic version；step claim 使用唯一键、lease、heartbeat 与 claim token fencing。
- 重复 HTTP 请求、并发重复消费和显式重复 broker 消息不会创建重复的逻辑 run/step。
- Reconciler 对已发布但未完成的当前版本事件执行重开；活动 lease 不会被抢占，过期 lease 可重新 claim，旧 worker 无法 finalize。
- 黑盒测试实际停止 worker 后创建任务并重复投递消息，worker 恢复后任务完成；API 重启后仍可查询已完成任务。
- 取消请求在 worker checkpoint 转为 `CANCELLED`；终态不再产生下一个 outbox event。
- Timeline 来自 PostgreSQL 持久化状态版本；SSE 使用版本作为 event id，`Last-Event-ID` 恢复不重复已确认事件，终态流自动结束。
- API、worker、Control PostgreSQL、Redis 四服务在清洁卷验证中均 healthy；worker UID 为非 root 的 `10001`。
- 验证结束后容器、网络和 Control PostgreSQL 测试数据卷已清理。

本里程碑的 stage handler 是确定性的 `m1.noop.v1`。到达 `COMPLETED` 只证明可靠任务编排骨架成立，不代表输入仓库或 Migration 已经过安全审计。
