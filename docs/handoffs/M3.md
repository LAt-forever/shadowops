# M3 受限 Fake Agent 规划验证交接

验证日期：2026-08-28（Asia/Shanghai）

分支：`codex/m3-bounded-fake-agent`

## 已验证范围

- `PLANNING` 使用真实 `m3.planning.v1` handler；相同 run 重放时直接读取已提交 plan，不重复创建 invocation、tool calls 或 plan。
- `AuditPlanV1` 是 extra-forbid 的版本化 Pydantic/JSON Schema 契约，只接受 allowlisted capability、DAG 依赖、timeout、reason、coverage gaps 与 evidence refs。
- 固定 capability catalog 包含 provision、baseline upgrade、target apply、test data、smoke checks、rollback roundtrip、evidence collection 与 cleanup；Agent 不能修改 capability 实现或预算上限。
- Plan Validator 拒绝未知/重复 capability、缺失 mandatory step、非 required mandatory step、越界 timeout、无效 evidence ref、缺失依赖、前置 capability 不满足和依赖环。
- Agent 输出结构中不存在 command、image、network 或 host path 逃生字段；只读 Tool Gateway 对未知工具和额外参数 fail closed。
- Tool Gateway 只从已信任的 M2 持久化结果与不可变 snapshot 读取：migration graph、指定 revision、static findings、capability catalog 和测试数据 coverage gap。
- Fake Provider 对相同输入生成固定八步 reference plan；runtime 记录 prompt/tool schema version、输入/输出 hash、provider/model、修复次数和稳定 trace identity，并把单次 revision 读取限制为 16 个、Provider 输出限制为 256 KiB。
- 首次 JSON/schema/plan 无效时只进行一次修复；第二次仍无效则持久化失败 invocation，并以稳定 `PLAN_INVALID` 终止 run。
- `agent_invocations`、`agent_tool_calls` 与 `audit_plans` 通过 `0005_agent_planning` 持久化；重复保存收敛到同一 invocation/sequence/run。
- `GET /api/v1/runs/{id}/plan` 对未知 run 返回 `404 RUN_NOT_FOUND`，对尚未生成计划的 run 返回 `409 AUDIT_PLAN_NOT_READY`。
- plan 和 static report 在 API restart 后保持一致；Worker restart、重复 broker 消息、取消和稳定失败路径继续由可靠任务骨架覆盖。
