# M4 Docker Resource Manager 与 Alembic upgrade 验证交接

验证日期：2026-08-30（Asia/Shanghai）

分支：`codex/m4-docker-resource-manager`

## 已验证范围

- 确定性 orchestrator 只执行 M3 已校验计划中的 provision、baseline upgrade、target apply 与 cleanup；Agent 仍不能控制 Docker、命令、镜像、网络或宿主路径。
- `RunnerRequestV1` / `RunnerResultV1` 是 extra-forbid 的版本化契约；Runner 使用固定 entrypoint 与 content-addressed image ID，并返回受大小限制、带 SHA-256 的 stdout/stderr artifact。
- 每个 run generation 使用独立 internal network、PostgreSQL 16 容器、数据卷与只读 snapshot 卷；资源带 run、generation、role 与 lease 标签。
- Runner 使用 UID/GID `10002:10002`、read-only rootfs、`cap_drop=ALL`、`no-new-privileges`、只读 snapshot mount、无 Docker socket，并受 CPU、内存、PID、statement 与 wall-clock 限制。
- Runner 只收到临时 shadow DB 凭据与固定请求；拿不到控制库 DSN、LLM secret 或任意宿主路径。
- safe fixture 从 baseline 升级到 target；broken fixture 返回持久化的结构化 `MIGRATION_FAILED`；slow fixture 在执行中取消后收敛为 `CANCELLED`。
- 相同 environment/action 的执行持久化并幂等重放，不会重复 apply。
- finalizer 以标签重试清理容器、network 与 volumes；周期 Sweeper 回收过期 lease。成功、失败、取消三条路径均验证零动态资源残留。
- 取消 outbox 重投递不会在活跃 stage 旁创建并发 `CANCELLED` claim；原执行者在 heartbeat checkpoint 完成取消，避免提前拆除 Runner。
- `shadow_environments` 与 `runner_executions` 由 `0006_dynamic_sandbox` 持久化；`GET /api/v1/runs/{id}/dynamic-result` 返回环境与执行结果。
