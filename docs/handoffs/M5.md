# M5 数据、Smoke Checks 与 Rollback Roundtrip 验证交接

验证日期：2026-08-30（Asia/Shanghai）

分支：`codex/m5-dynamic-evidence`

## 已验证范围

- 确定性 orchestrator 在 M4 target upgrade 后固定执行 seed、schema/row/constraint smoke、`target → baseline → target` rollback roundtrip 与 evidence collection；Agent 仍不能控制 SQL、Docker、命令、镜像、网络、凭据或宿主路径。
- `shadowops-fixture.json` 使用固定 `1.0` schema，并限制标识符、JSON scalar、单值大小、表数和总行数；缺少 manifest 时只对受支持的基础类型生成有限确定性数据。
- 外键、不支持的数据类型和缺失 baseline schema 不会被误报为已覆盖，而是形成持久化的 coverage gap。
- smoke checks 记录规范化 schema fingerprint、逐表 row count、约束数量与未验证约束，不读取或返回实际业务行值。
- rollback roundtrip 比较最终 revision、schema fingerprint 与 row-count map；失败时返回稳定的 `ROLLBACK_FAILED`，并尽力恢复到 target revision。
- Runner observation 采用版本化、extra-forbid 契约和 canonical JSON SHA-256；stdout/stderr 继续受大小限制并在持久化前脱敏。
- 本地 artifact store 使用 content address、同目录临时文件、file/directory `fsync`、`0600` 权限与原子 rename；控制库只保存 URI、hash、大小、scope 和 redaction metadata。
- evidence 明确区分 `observed_in_shadow` 与 `unknown_in_production`；shadow seed/smoke 成功不代表生产数据分布、锁行为或兼容性已覆盖。
- safe fixture 验证 seed 后 row count 在 `002 → 001 → 002` 往返中保持不变；唯一冲突、不可逆 downgrade、类型转换失败与不支持类型 fixture 分别产生预期的结构化错误或 coverage gap。
- 成功与失败路径均在 evidence collection/finalizer 后清理每次运行的 Runner、PostgreSQL container、internal network 和动态 volumes；控制库与 artifact 测试卷按安全约束保留。
