# M6 真实 Agent、风险报告与确定性 Policy Engine 验证交接

验证日期：2026-09-05（Asia/Shanghai）

分支：`codex/m6-risk-reporting`

## 已验证范围

- Provider-neutral `LLMProvider` 边界提供 Fake、Recorded 与 OpenAI Responses API live 三种模式；模型和 credential 只由受信任 worker 配置，domain、API 与 Runner 都不依赖或接收密钥。
- OpenAI adapter 使用 strict JSON Schema、`store=false`、固定 token/timeout/attempt budget 和 prompt 脱敏；同时兼容 REST output blocks，并把 timeout、rate limit、provider failure 与无效响应映射为稳定诊断。
- Planner 继续只能生成 allowlisted capability plan；Reporter 只能读取固定静态报告、计划、step results、evidence metadata/content 与 schema diff 视图，不能触发 shell、Docker、SQL、网络、审批或其他副作用。
- `ReporterDraftV1` 的事实条目必须引用本次只读观察中存在的 evidence id；schema 或 citation 错误只修复一次，预算耗尽后持久化带失败诊断的确定性 fallback report。
- `RiskReportV1` 持久化 canonical report hash、input hash、draft、完整 evidence ids、最终风险、policy reasons，以及 provider/model/response/token/latency/error metadata；同一 report input 幂等收敛。
- 确定性 Policy Engine 聚合静态严重度、动态失败、mandatory evidence 缺口与 coverage gap；模型可提高但不能降低安全下限。高风险报告标记 `requires_approval`，成功的高风险 run 停在 `AWAITING_APPROVAL`。
- 动态失败路径会在资源 finalizer/evidence collection 后尽力生成风险报告，再以原稳定失败码结束；rollback failure、危险静态 finding 与 unsupported seed coverage gap 均在 E2E 中得到预期 policy 结果。
- `GET /api/v1/runs/{id}/risk-report` 返回完整版本化报告；run view 使用 `m6.evidence-risk-report.v1` profile 并提供 risk report link。
- 默认 Compose/CI 使用 Fake Provider，不需要或调用真实 API key；Named control/artifact 验证卷按安全约束保留。
